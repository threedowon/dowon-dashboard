Signal별 쿨다운
Signals 카드의 편집창에서 Cooldown을 설정하세요. 기본 3초이며 0은 제한 없음입니다. 같은 Signal의 센서·키보드·수동·반복 전송은 대상 Player와 관계없이 쿨다운을 공유합니다. SceneCast와 센서 규칙에는 별도 쿨다운이 없습니다.
센서와 키보드 테스트


기존 Serial 또는 UDP 연결을 선택해 Add sensor로 센서 모니터를 추가하세요. Number 또는 JSON 필드를 선택하고 Below / Above 조건을 추가하세요. 센서 연결을 열면 그래프가 표시되며, Enable all rules를 누르면 각 규칙에 지정한 Player로 Signal을 전송합니다. EXE 전용 창을 닫으면 규칙과 통신이 종료됩니다. Python으로 실행한 브라우저 화면은 탭만 닫아도 규칙이 계속 실행됩니다. Pause all rules는 대기 중인 전송을 멈추지만 이미 보낸 요청은 취소할 수 없습니다.


Signal 편집창에서 Choose key를 누르고 목록에서 키를 선택하거나 키보드로 직접 누르세요. Keyboard test를 켜고 전송할 Player를 선택하세요. 테스터 화면에 포커스가 있을 때만 전송하며, 입력칸에 글자를 입력하거나 대화상자가 열려 있을 때는 전송하지 않습니다. 운영체제 전용 단축키는 Windows나 브라우저에서 처리될 수 있습니다.


Serial 및 UDP


COM ports는 포트를 열거나 데이터를 보내지 않고 장치를 검색합니다. Use port로 Serial 연결을 만들고 장치 설명서에 맞게 통신 속도와 프레임 설정을 맞추세요. 같은 포트를 쓰는 다른 앱은 먼저 닫으세요.


Add connection → UDP에서 로컬 수신 주소와 원격 전송 주소를 따로 설정합니다. 모든 로컬 IPv4 인터페이스에서 수신하려면 0.0.0.0을 사용하세요. 로컬 포트를 0으로 설정하면 사용 가능한 포트가 자동 선택됩니다.


Open connection을 누르면 수신을 시작합니다. Raw data는 텍스트 또는 HEX 바이트를 전송합니다. Sent는 장치가 수신했다는 뜻은 아닙니다. Activity에서 별도의 RX 이벤트와 오류 단계를 확인하세요.


Pause view는 화면의 로그 표시만 멈춥니다. EXE의 프로그램 종료 버튼이나 창의 ×를 누르면 수신과 연결도 종료됩니다. Python 브라우저 방식에서는 연결을 닫거나 실행 콘솔을 종료하세요. 엔진을 다시 시작하면 모든 연결은 닫힌 상태로 시작합니다.

  1. Start the Player receiver.
    Open Player settings with Shift + F. In Signals, enable the HTTP receiver and note its port.
  2. Choose a target.
    Use 127.0.0.1 for a Player on this PC. For multiple Players, save a different port for each one. Check before testing.
  3. Add your keys.
    Import a .scene or add a Signal manually. The key must match Editor → Signals. Import adds new keys and keeps your existing values.
  4. Send and inspect.
    A card's Send button sends its saved value. The Selected signal panel sends your current value. Each card shows its latest result. Click Activity to see why a scene changed—or why it did not.
Per-Signal cooldown
Set Cooldown in Edit signal. The default is 3 seconds; 0 disables the limit. Sensor, keyboard, manual and repeat sends share the same cooldown for each Signal across all Player targets. SceneCast and sensor rules have no separate cooldown.
Sensors & keyboard tests
Add a sensor monitor using an existing Serial or UDP connection. Select Number or a JSON field, then add Below / Above rules. Open the source connection to see the graph; Enable all rules sends to each rule’s selected Player. Closing the EXE window stops rules and communication. In Python browser mode, rules continue when only the tab closes. Pause all rules stops queued sends; requests already sent cannot be recalled.
Edit a Signal and click Choose key: select from the list or press the physical key. Enable Keyboard test and choose its output Player. Keys only send when this page is focused; typing in fields and open dialogs never triggers a send. OS-reserved shortcuts may still be handled by Windows or the browser.
Serial & UDP
COM ports discovers devices without opening them. Use port creates a Serial profile; match baud and framing settings to the device manual. Close other apps using that port first.
Add connection → UDP separates the local receive address from the remote send address. Use 0.0.0.0 to receive on all local IPv4 interfaces. Local port 0 chooses an available port.
Open connection starts receiving. Raw data sends Text or exact HEX bytes. Sent does not confirm device receipt. Inspect separate RX events and the error stage in Activity.
Pause view freezes the visible log only. The EXE Exit button or window × stops receiving and closes connections. In Python browser mode, close connections here or stop the launch console. Restarting the engine leaves all connections closed.
