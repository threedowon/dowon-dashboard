# Signal Tester 사용법

Player의 HTTP Signal과 **Serial·UDP 송수신을 한 화면에서 확인**하는 테스트 도구입니다. 센서값 실시간 그래프, 조건에 따른 자동 Signal 전송, 키보드 테스트를 지원합니다. 연결 설정·Signal 키·키보드 바인딩·센서 규칙을 저장해 다음 테스트 때 그대로 사용할 수 있습니다. UI의 설정과 통신은 센서가 연결된 PC의 Python 프로그램이 처리합니다.

## SEN0610 / FSR을 여기서 함께 보기

**[SignalTester.exe](https://github.com/threedowon/dowon-dashboard/releases/latest/download/SignalTester.exe) 하나**로 실행합니다. 왼쪽 **센서 대시보드** 또는 **Sensors**에서 등록한 센서를 함께 봅니다. 상단 센서 구성 추가 패널은 제거했으며, 기존 설정은 유지됩니다. 새 모니터는 **Add sensor**로 추가하세요.

- SEN0610은 거리·Near(30~60cm)·Ready·Error 4개, FSR은 원본값 4개·증가량 4개·Detected·Ready·Calibrating·Error 12개를 표시할 수 있습니다. 함께 등록하면 16개 모니터를 같은 화면에서 봅니다.
- **표시할 연결**에서 전체 또는 센서별로 필터링하고, 현재값 카드를 누르면 상세 그래프가 바뀝니다. 수신이 끊기면 마지막 값은 흐리게 표시하고 상태를 함께 표시합니다. 필터는 표시만 바꾸며 수신/자동 규칙을 끄지 않습니다.
- 각 Serial 연결의 포트를 실제 보드에 맞게 변경한 뒤 **Open connection**을 누르세요. COM3/COM4는 예시입니다. 두 보드가 같은 COM 포트를 쓰도록 설정하지 마세요.
- **동시에 측정하려면 각각의 펌웨어가 올라간 보드 2대가 필요합니다.** 하나의 ESP32-S3로 번갈아 시험하려면 펌웨어를 바꿔 올리고 해당 연결만 여세요. 통합 화면이 두 펌웨어를 하나로 합치는 것은 아닙니다.
- FSR은 **3.3V / GPIO1·2·4·5 / 10kΩ 각각 1개**입니다. 상판·러그만 올린 후 FSR 연결의 Serial → Raw data → Text / LF에서 `c`를 전송하고 Ready=1을 확인하세요. 임계값 변경 예: `t 1 80 40`.
- 영상 규칙은 각 센서의 near/detected가 1초 유지될 때 기본 키 `person`을 전송합니다. 두 규칙을 함께 켜면 같은 키와 쿨다운을 공유합니다. 비교 시험은 **규칙을 정지한 상태**에서 하고, 필요하면 Configure에서 한쪽 규칙만 활성화하거나 Signal 키를 구분하세요.
- 예전 별도 폴더의 `.local.json`은 자동으로 읽거나 덮어쓰지 않습니다. 기존 별도 테스터 설정을 가져오려면 먼저 Export로 백업하고 Import한 뒤 필요한 모니터를 Add sensor로 추가하세요. Import 자체는 기존 기능대로 workspace를 교체합니다.

펌웨어와 배선 안내도 이 폴더의 **[devices](devices/README.md)** 아래에서 찾을 수 있습니다. 별도 SEN0610/FSR 폴더를 열 필요가 없습니다. 기존 폴더는 이전 작업과의 호환을 위해 남아 있습니다.

## 실행

1. `SignalTester.exe`를 더블클릭합니다. Windows 10/11 64비트용이며 Python과 Serial 지원이 포함되어 있습니다. 별도 설치나 연결 코드 입력은 필요 없습니다. 소스로 실행하려면 [개발 안내](README.md#소스-실행개발)를 참고하세요.
2. 브라우저에 테스트 화면이 열립니다. 실행한 콘솔 창은 열어 두세요. 종료할 때는 콘솔에서 `Ctrl + C`를 누릅니다.
3. Player에서 `Shift + F` → **Signals**를 열고 HTTP 수신기를 켭니다. 표시된 수신 포트를 확인합니다.
4. Tester 왼쪽 **This PC**의 연필 버튼에서 포트를 맞춥니다. 같은 PC라면 IP는 `127.0.0.1`입니다.
5. **Check**을 눌러 `Receiver ready`가 표시되는지 확인합니다. 연결 확인은 Signal을 전송하지 않습니다.

브라우저 주소에 표시되는 포트는 테스트 화면의 주소입니다. 왼쪽 Target의 포트가 **Player에 신호를 보내는 포트**입니다.

같은 `SignalTester.exe`를 다시 실행하면 **그 파일로 실행 중인 Tester를 종료하고 하나만 다시 실행**합니다. 여러 번 실행해도 마지막 실행 하나가 남습니다. Serial·UDP 연결과 자동 규칙을 정리한 뒤 종료하며, 응답하지 않는 Tester는 종료시킨 뒤 교체합니다. 다른 경로의 EXE, 소스로 실행한 Tester, Player는 종료하지 않습니다. 소스용 `Start-Signal-Tester.cmd`도 같은 폴더의 Python Tester에 대해 자동 교체를 지원합니다.

저장한 대상·Signal·센서 규칙은 유지됩니다. 연결은 닫힌 상태, 자동 규칙과 키보드 테스트는 일시 정지 상태로 시작합니다. 브라우저의 이전 탭은 자동으로 닫지 않으므로 **새로 열린 페이지**를 사용하세요.

## Serial: COM 포트 검색과 송수신

1. 왼쪽 **COM ports**를 누릅니다. 포트 이름·장치 설명·제공되는 USB 식별 정보를 볼 수 있습니다. 자동 검색은 약 2초마다 갱신되며, 이 단계에서는 포트를 열거나 데이터를 보내지 않습니다.
2. 원하는 장치의 **Use port**를 누르거나, **Add connection → Connection type: Serial**을 선택합니다.
3. 이름·COM 포트·Baud rate를 설정합니다. 센서 설명서에 맞춰 Data bits / Parity / Stop bits도 설정하세요. 기본은 115200 / 8 / None / 1입니다.
4. **Save** 후 왼쪽에서 해당 연결을 선택하고 **Open connection**을 누릅니다. 같은 COM 포트를 다른 센서 프로그램이 사용 중이면 해당 프로그램에서 먼저 연결을 해제해야 합니다.
5. 가운데 **Raw data**에 전송할 내용을 입력하고 **Send data**를 누릅니다. Text는 UTF-8, HEX는 `AA 01 0D 0A`처럼 정확한 바이트입니다. Text에서는 None / LF / CRLF / CR 줄바꿈을 선택할 수 있습니다. HEX에는 줄바꿈을 자동 추가하지 않습니다.
6. **Latest received data**에서 최근 수신 데이터를 Text / HEX로 바꿔 볼 수 있습니다. 모든 연결의 기록은 오른쪽 Activity에 함께 쌓입니다.

**Device detected → Port open → Receiving → Sending**을 각각 표시합니다. 포트가 보인다고 사용 가능한 것은 아니고, 포트가 열렸다고 센서 데이터가 정상이라는 뜻도 아닙니다. 수신이 없으면 `Waiting for data`가 표시됩니다. 케이블 분리·장치 오류는 발생 단계와 함께 기록됩니다. 재연결은 문제를 해결한 뒤 **Open connection**으로 수행합니다.

Latest received data와 Activity의 RX 표시는 **원본 바이트 단위**입니다. 한 기록이 메시지 하나와 일치하지 않을 수 있고, 하나의 메시지가 여러 수신 기록으로 나뉠 수 있습니다. UTF-8 문자가 중간에서 나뉘거나 이진 프로토콜이면 Text에 대체 문자가 보일 수 있으므로 HEX도 확인하세요. **Sensors** 탭는 이 원본 데이터에서 완성된 숫자 메시지를 조립해 그래프와 조건에 사용합니다.

## UDP: 전송과 수신 대기

1. **Add connection → Connection type: UDP**를 선택합니다.
2. **Local bind IP / Local port**는 이 도구가 수신할 주소입니다. 같은 PC끼리는 `127.0.0.1`, 외부 장치에서 받을 때는 이 PC의 해당 네트워크 IP 또는 `0.0.0.0`을 사용합니다. 포트 `0`은 사용 가능한 포트를 자동 할당하며, 연 뒤 실제 포트를 진단 패널에서 확인할 수 있습니다.
3. **Remote IP / Remote port**는 데이터를 보낼 상대 장치의 주소입니다. 브로드캐스트 전송이 필요할 때만 **Allow broadcast sends**를 켭니다. 현재 UDP 기능은 IPv4를 사용합니다.
4. **Open connection**을 누르면 로컬 소켓이 열리고 `Listening`이 표시됩니다. 같은 소켓에서 송수신하므로, 상대가 보낸 주소로 응답하면 Activity의 RX에 도착합니다.
5. Raw data에서 Text 또는 HEX를 전송합니다. 반복 테스트도 사용할 수 있습니다.

**UDP의 Listening은 로컬 수신 준비 완료이며 상대 장치의 접속 성공이 아닙니다.** `Datagram sent`는 로컬 소켓에 전달됐다는 뜻이고, 상대 수신을 보장하지 않습니다. 상대 응답이 있으면 별도 RX 기록으로 표시되며, 어떤 TX의 응답인지는 프로토콜을 확인해야 합니다. UDP 자체에는 자동 수신 확인이나 재전송이 없습니다.

센서 없이 **같은 PC에서 UDP 왕복 시험**을 하려면 Local bind IP와 Remote IP를 `127.0.0.1`, 양쪽 포트를 같은 빈 번호(예: 19020)로 설정하세요. 열고 전송하면 자신의 데이터가 RX로 돌아옵니다. 이미 다른 프로그램이 포트를 사용 중이면 `Local port already in use`와 `open` 단계 오류가 표시됩니다.

외부 장치에서 수신되지 않으면 장치의 목적지 IP가 이 PC의 IP인지, Local bind IP와 포트가 맞는지, Windows Firewall이 수신을 허용하는지 확인하세요. 테스터가 UDP를 지원해도 Player에 UDP 수신 기능이 자동 추가되는 것은 아닙니다. Player Signal은 기존 HTTP 방식으로 전송합니다.

## 센서 그래프와 자동 Signal 전송

예: 센서가 cm 단위로 거리를 보내고, 가까워지면 `person`, 멀어지면 `person_far`를 보내고 싶을 때:

1. **Add connection**으로 센서의 Serial 또는 UDP 수신 연결과 Player의 HTTP 연결을 등록합니다. Signals에 `person`, `person_far`를 추가합니다. Player 프로젝트에도 같은 키가 있어야 합니다.
2. 센서 연결을 선택해 **Open connection**을 누릅니다.
3. **Sensors** 탭 → **Add sensor**를 누르고 **Receive from**에서 센서 연결을 선택합니다.
4. `120.5`처럼 숫자만 받으면 **Message format: Number**를 선택합니다. `{"distance":120.5}`처럼 JSON을 받으면 **JSON field**, 경로는 `distance`로 설정합니다. 중첩 값은 `sensor.distance`, 배열은 `values.0`처럼 지정합니다. 문자열 `"120"`, boolean, NaN은 숫자로 취급하지 않습니다.
5. **Display unit**을 `cm`로 설정합니다. 이것은 표시 이름이며 값을 환산하지 않습니다. 센서가 mm를 보내면 `mm`와 그에 맞는 임계값을 사용하세요.
6. **Add rule**로 첫 규칙을 만듭니다: **Below (<) / Threshold 100 / Send Signal person / To Player 원하는 Player**.
7. 두 번째 규칙은 **Above (>) / Threshold 150 / Send Signal person_far**로 만듭니다. 각 규칙의 Player 대상은 왼쪽에서 선택한 연결과 별개로 고정됩니다.
8. **Save sensor** 후 그래프를 확인합니다. **Enable all rules**를 눌러야 자동 전송을 시작합니다. 켜는 순간 저장된 과거 값은 전송하지 않고, 새로 수신한 값부터 판정합니다.

그래프는 최근 60초를 보여주며 점선은 각 규칙의 임계값입니다. 그래프 표시는 최대 초당 약 10점·600점으로 제한하지만 **규칙은 수신한 모든 유효 값을 판정**합니다. 브라우저 갱신 간격은 약 0.65초이며 실시간 제어용 정밀 계측 그래프는 아닙니다. **Freeze graph**는 선택한 상세 그래프만 멈추며 현재값 카드·수신·자동 전송은 계속됩니다. 센서 모니터는 최대 32개, 센서당 규칙은 최대 16개입니다.

규칙 설정:

- **Hold**: 조건을 연속으로 만족해야 하는 시간입니다. 기본값은 `0`초로, 조건을 만족하는 첫 값에서 즉시 전송합니다. 0보다 크게 설정하면 센서가 값을 계속 보내야 하며, 시간이 지났어도 다음 유효 값이 도착할 때 판정합니다. 일회성 측정은 `0`을 사용하세요.
- **Reset margin**: 경계 주변의 흔들림을 무시하는 여유값입니다. Below 100 / margin 10이면 한 번 보낸 뒤 **110 이상**이 되어야 다시 준비됩니다. Above 150 / margin 10이면 **140 이하**에서 다시 준비됩니다. 임계값 자체와 같은 값은 Below/Above 조건을 충족하지 않습니다.
- **Signal별 Cooldown**: Signals 카드의 편집창에서 설정합니다. 기본값은 `3`초이며 `0`이면 제한하지 않습니다. 같은 Signal 키의 센서·키보드·수동·반복 전송은 대상 Player와 관계없이 하나의 쿨다운을 공유합니다. 센서 규칙에는 별도 쿨다운이 없습니다. 감지 조건이 해제된 뒤 재진입해야 하며, 쿨다운 중 재진입하면 시간이 지난 뒤 조건을 만족하는 새 데이터가 들어올 때 전송합니다. 수동·키보드 전송은 쿨다운 중 대기열에 넣지 않고 건너뜁니다. 전송 실패도 시도 시점부터 쿨다운을 적용합니다.
- 기존 설정에 Signal 쿨다운이 없으면 3초를 적용합니다. 예전 센서 규칙의 쿨다운은 제거되며, SceneCast의 예전 쿨다운 값은 적용하지 않습니다.
- **Signal value**: `Sensor reading`은 판정 시점의 숫자, `Saved Signal value`는 Signal에 저장된 기본값을 보냅니다.
- **Data timeout**: 유효 값이 이 시간 동안 없으면 `Data timeout`으로 표시하고 유지 시간 판정을 새로 시작합니다. 기본 2초입니다. 데이터 없음이나 파싱 실패를 자동으로 `person_far`로 간주하지 않습니다.
- 각 규칙의 체크박스를 끄면 그 규칙만 제외합니다. 서로 다른 규칙은 독립적이므로 조건이 겹치면 둘 다 보낼 수 있습니다.

메시지 경계:

- **Serial**: 숫자 또는 JSON 뒤에 LF / CRLF / CR 줄바꿈이 필요합니다. 메시지가 여러 번에 나뉘어 도착해도 합칩니다. 줄바꿈이 없으면 완성된 값으로 처리하지 않습니다.
- **UDP**: 데이터그램 한 개가 완성된 숫자 또는 JSON이어야 합니다. 한 데이터그램 안의 여러 줄도 처리합니다. 데이터그램 사이에 나뉜 JSON은 조립하지 않습니다.
- 메시지는 최대 4096바이트이며 이진 센서 프로토콜을 자동 해독하지 않습니다. 이진 센서는 기존 Python 코드에서 숫자/JSON으로 변환해 UDP로 보내거나 별도 파서를 추가해야 합니다.

**Receiving → 규칙 상태 → Last output**으로 수신·조건 판정·Player 응답을 확인합니다. 형식 오류는 **Parse error**와 Activity의 `parse` 단계로, 전송 결과는 **Sensor · 모니터 이름**으로 기록됩니다. 같은 파싱 오류 로그는 과다 표시를 막기 위해 최대 2초에 한 번 기록하고 오류 횟수는 모두 셉니다. 신호 전송 실패는 자동 재시도하지 않습니다.

**Pause all rules**는 다음 전송과 대기 중인 전송을 멈춥니다. 이미 전송 중인 요청은 취소할 수 없습니다. 출력 요청이 밀리면 오래된 측정의 전송은 생략하며 상태에 표시합니다. 브라우저를 닫아도 Python이 켜져 있으면 센서 수신과 활성 규칙은 계속됩니다. 프로그램 재시작, 센서/규칙 수정, 참조하는 Signal 키·값이나 연결 설정 변경 후에는 규칙이 일시 정지되므로 다시 확인하고 활성화하세요. 단순히 왼쪽 연결을 선택하거나 페이지를 새로고침하는 것은 실행 중인 규칙에 영향을 주지 않습니다.

센서가 없어도 UDP 자기 송수신 연결(위 절)을 만든 뒤 `80`, `160`을 **Send data**로 보내면 그래프와 분기를 시험할 수 있습니다. 실제 Player의 장면 전환을 시험하려면 수신기가 실행 중이어야 합니다.

## Signal에 키보드 키 지정하기

1. HTTP 연결을 선택해 Signals 목록을 열고 Signal의 연필 버튼을 누릅니다.
2. **Keyboard test key → Choose key…**를 누르면 키 목록이 펼쳐집니다. 목록에서 선택하거나, 펼쳐진 상태에서 원하는 키를 직접 누릅니다. Escape는 입력 대기를 취소하고, **Clear**는 바인딩을 없앱니다.
3. **Save**로 저장합니다. Signal 카드에 할당한 키가 표시됩니다. 같은 키를 두 Signal에 중복 지정할 수 없습니다.
4. **Keyboard test** 옆 **Send to**에서 Player 대상을 고르고 체크박스를 켭니다. 이제 Tester 화면에 포커스를 두고 지정한 키를 누르면 해당 Signal의 **저장된 값**이 전송됩니다. 왼쪽에서 다른 연결을 선택해도 키보드 출력 대상은 유지됩니다.

키를 길게 눌러도 한 번만 전송하며, 떼었다 다시 눌러야 재전송합니다. 입력칸 편집, 열린 대화상자, Ctrl/Alt/Shift/Windows 조합에서는 전송하지 않습니다. 문자·숫자·방향키·Space·기능키·숫자패드 등을 지원합니다. 키보드의 물리적 키 위치를 사용하므로 한/영 입력 상태와 무관합니다. 운영체제가 먼저 처리하는 키는 브라우저에서 잡지 못할 수 있습니다. 테스트 중 다른 전송 작업이 진행 중이면 추가 키 전송을 대기열에 넣지 않고 안내합니다.

이 기능은 **Tester 페이지가 활성화된 동안만** 동작합니다. Player 창이 포커스를 가진 상태에서 쓰는 전역 단축키와는 다릅니다. 페이지를 다시 열면 Keyboard test는 꺼져 있으며, 할당한 키는 저장되어 있습니다. 기존 전역 `keys` 모드는 아래 절을 참고하세요.

## 통합 로그와 문제 위치

Activity 패널 왼쪽 경계에 마우스를 올린 뒤 왼쪽으로 드래그하면 로그 영역이 넓어집니다. 더블클릭하면 기본 너비로 돌아갑니다. 너비는 같은 브라우저에 저장되며, 좁은 화면에서는 패널이 아래로 배치되어 드래그 기능을 숨깁니다. 경계에 키보드 포커스를 두고 좌우 방향키로도 조절할 수 있습니다. 긴 로그는 확보한 너비만큼 표시되고, 전체 내용은 해당 기록을 클릭해 확인합니다.

- **Activity**에는 HTTP·Serial·UDP 기록이 함께 표시됩니다. 프로토콜, TX / RX / System, 오류만 보기, 현재 연결만 보기로 필터링할 수 있습니다.
- **TX**는 전송, **RX**는 수신, **System**은 연결 열기·닫기·연결 오류입니다. `open`, `receive`, `send`, `parse`, `rule`, `response`로 문제가 생긴 단계를 표시합니다. 센서/키보드 전송은 `Sensor · …`, `Keyboard · …` 출처도 기록합니다.
- 기록 클릭: 연결 정보, 원본 Text·HEX, 바이트 수, 상대 주소, 운영체제 오류 또는 Player 응답을 확인합니다. HEX와 Text는 원본의 앞 2 KB 미리보기이며 더 긴 데이터는 잘림을 명시합니다. 전송은 줄바꿈 포함 최대 8 KB입니다.
- **Pause view**는 화면 목록만 일시 정지합니다. Python 엔진의 수신·기록은 계속됩니다. Resume view를 누르면 최신 기록을 봅니다.
- 최근 500개를 메모리에 보관하고 화면에는 최대 200개를 표시합니다. 매우 빠른 입력이나 브라우저 백그라운드 상태로 화면 갱신을 따라가지 못하면 건너뛴 기록 수를 표시합니다. 모든 바이트의 영구 녹화 기능은 아닙니다.
- 다운로드 아이콘은 현재 브라우저에 보관된 최근 통합 로그를 JSON으로 내보냅니다. 필터와 관계없이 해당 목록 전체를 내보냅니다.

예를 들어 **포트 사용 중/권한 부족 → open**, **USB 분리 → receive**, **쓰기 제한 시간 초과 → send**로 표시합니다. 오류 문구는 가능한 원인을 안내하지만, 다른 프로그램의 이름이나 센서 내부 고장까지 자동 확정하지는 않습니다.

## 연결의 수명

- 여러 Serial·UDP 연결을 동시에 열 수 있습니다(최대 16개). 왼쪽에서 다른 연결을 선택해도 이미 열린 수신기는 계속 동작합니다.
- 연결 설정을 바꾸거나 해당 연결을 삭제하면 기존 연결을 닫습니다. 변경된 설정으로 다시 열어 주세요. 다른 연결의 수신은 유지합니다.
- 브라우저를 닫거나 새로고침해도 **Python 프로그램이 실행 중이면 열린 Serial·UDP 수신은 계속됩니다.** 브라우저에서 실행한 반복 전송은 페이지를 닫으면 중단됩니다.
- 종료하려면 각 연결의 **Close connection** 또는 실행 콘솔의 `Ctrl + C`를 사용합니다. 엔진을 새로 실행하면 저장된 연결은 모두 닫힌 상태로 시작합니다. 물리 센서를 자동으로 열지 않습니다.
- 엔진과 화면의 연결이 끊기면 상태가 확인되지 않는다는 안내를 표시합니다. 엔진을 재시작했다면 새로 출력된 주소로 화면을 여세요.

## 대상과 키 관리

- **Add connection**: 이름·IP/호스트·포트를 등록합니다. 같은 PC의 Player를 여러 개 시험할 때는 수신 포트를 각각 다르게 설정하고 Target을 따로 만드세요.
- Target 클릭: 해당 대상으로 전송합니다. 위쪽 **SENDING TO**에서 현재 대상을 확인합니다.
- 연필 버튼: 이름/IP/포트 또는 Signal 이름/키를 수정합니다. 편집 창의 **Delete**는 Tester에서만 삭제하며 Player나 `.scene` 파일은 수정하지 않습니다.
- **Add signal**: 표시 이름과 키를 입력합니다. 키는 Editor → Signals에 등록한 키와 같아야 하며 소문자로 저장됩니다.
- **Import .scene**: 파일에 등록된 Signal과 조건의 Signal 키를 가져옵니다. 새 키만 추가하고 기존 키의 저장된 값은 보존합니다. 원본 `.scene`을 수정하지 않습니다.
- **Search**: 이름이나 키로 원하는 Signal을 찾습니다.

현재 Player 수신기는 **같은 PC 접속만** 허용합니다. 다른 PC에서 시험하려면 이 Tester를 해당 Player PC에서 실행하세요. IP 입력 기능은 네트워크 수신을 지원하는 수신기에도 사용할 수 있지만, IP만 바꾼다고 현재 Player의 원격 수신이 활성화되지는 않습니다.

## 전송과 반복 테스트

- 카드의 **Send** 버튼: 해당 Signal의 **저장된 값**을 즉시 전송합니다.
- 카드 이름/키 클릭: Selected signal 패널에서 해당 Signal을 선택합니다.
- **Value**: 없음(null), 숫자, 문자열, boolean을 선택합니다. 아래 JSON Payload에서 실제 전송 내용을 확인하고 복사할 수 있습니다.
- **Send signal** 또는 `Ctrl + Enter`: Selected signal 패널의 **현재 값**을 한 번 전송합니다. 단축키는 Tester 페이지에 포커스가 있을 때 작동합니다.
- **Save as default value**: 현재 값을 카드의 기본값으로 저장합니다. 값을 임시로 바꿔 보내는 것만으로는 기본값이 바뀌지 않습니다.
- **Repeat test**: 횟수(2~1000)와 간격(0.2~3600초)을 정하고 **Start repeat**를 누릅니다. 첫 신호는 즉시 전송하며, 응답을 받은 후 설정한 간격만큼 기다렸다 다음 신호를 보냅니다.
- **Stop** 또는 `Esc`: 다음 전송을 중지합니다. 이미 보낸 요청은 취소할 수 없습니다. 연결 오류가 생겨도 반복은 중단됩니다.
- 반복 중에는 대상·키·값 변경을 막아 다른 대상에 잘못 보내는 것을 방지합니다. 페이지를 닫거나 이동하면 반복은 끝납니다. 브라우저 백그라운드에서는 간격이 더 길어질 수 있으므로 정밀 타이밍 측정용은 아닙니다.

## Activity 결과 읽기

**Received는 수신 성공이지 장면 전환 성공을 뜻하지 않습니다.** 기록을 클릭하면 상세 설명, 보낸 JSON, Player 응답, 소요 시간을 볼 수 있습니다. **Send again**은 같은 신호를 한 번 더 보냅니다.

- **Scene changed**: 신호에 의해 장면이 바뀌었습니다.
- **Waiting for other triggers**: 신호는 조건을 충족했지만 다른 AND 트리거를 기다립니다.
- **No matching condition**: 신호는 도착했으나 현재 장면에 해당 조건이 없습니다.
- **Cooldown**: 설정한 재입력 대기 시간이 지나지 않았습니다.
- **Unknown Signal**: Player에 적용된 프로젝트에 해당 키가 없습니다. Editor에서 저장 후 Player에 적용하세요.
- **Playback stopped**: 재생 정지 또는 운영시간 외 상태입니다.
- **Transition in progress**: 이미 다른 장면으로 전환 중입니다.
- **Cannot reach receiver**: Player 수신기가 꺼졌거나 IP/포트가 다릅니다.
- **Request timed out**: 제한 시간 안에 응답을 받지 못했습니다. 자동 재전송하지 않으며, 요청이 도착했는지는 Player에서도 확인하세요.

최근 500개 기록을 실행 중인 Tester 서버 메모리에 보관합니다. 필터로 실패/전환 결과만 볼 수 있고 다운로드 아이콘으로 JSON 로그를 저장할 수 있습니다. 서버를 종료하면 기록은 사라집니다.

## 설정 저장과 이동

대상·키·기본값·키보드 바인딩·센서 및 규칙·선택한 대상은 `%LOCALAPPDATA%\SignalTester\dashboard-workspace.json`에 자동 저장합니다. EXE와 CMD는 기존 대시보드 설정을 이어서 사용합니다. 직접 `python signal_tester.py`로 실행하면 이전 로컬 `workspace.json`을 사용합니다. Player와 독립적인 Tester 설정이며, 같은 설정 파일을 동시에 여러 Tester에서 편집하지 않는 것이 좋습니다. 센서 규칙과 키보드 테스트의 실행 여부는 저장하지 않으며, 프로그램 시작 시 일시 정지 상태입니다.

- **Export**: 현재 설정을 JSON으로 내보냅니다.
- **Import**: 가져온 파일로 현재 목록 전체를 교체합니다. 확인 창에서 승인한 후 적용됩니다.
- 다른 Windows PC에는 `SignalTester.exe`만 복사하고 Export한 설정을 가져오면 됩니다. Python은 설치하지 않아도 됩니다. COM 번호와 네트워크 주소는 PC에 맞게 수정해야 합니다.
- 저장 파일이 손상되면 원본을 덮어쓰지 않고 오류를 표시합니다. 해당 파일을 백업한 후 복구하거나 다른 이름으로 옮기고 다시 실행하세요.

## 기존 명령 사용

업데이트 후 `Workspace not loaded`가 표시되면 `SignalTester.exe`를 다시 실행하세요. 소스로 실행 중이라면 `Start-Signal-Tester.cmd`를 사용합니다. 기존 Tester가 자동으로 종료되고 **새로 열린 주소의 페이지**에서 최신 버전을 사용할 수 있습니다. 저장한 대상·Signal은 그대로 유지됩니다. 일시적인 로딩 오류라면 **Retry loading**으로 다시 불러올 수 있으며, 목록을 읽기 전에는 추가·저장을 막아 기존 설정이 덮어써지지 않도록 합니다.

기존 `scenecast_tester.py panel` 및 인수 없는 실행도 새 화면을 엽니다. `keys`, `sensor`, `script`, `serial`, `ui`, `health` 모드는 그대로 사용할 수 있습니다. 실제 USB 센서 연결(`serial` / `ui --device`)은 기존처럼 `pyserial`이 필요합니다.

```powershell
python signal_tester.py
python signal_tester.py --host 127.0.0.1 --port 8421 --scene "D:\show\show.scene"
python signal_tester.py --config "D:\show\tester-workspace.json"
python ../SceneCast/examples/scenecast_tester.py keys --keys person person_far
```

기존 `keys` 모드의 Windows 전역 단축키는 `Ctrl + Alt + 1~9`입니다. Player가 포커스를 가진 상태에서 키보드 테스트를 할 때 사용하세요. 전역 단축키 종료는 `Ctrl + Alt + Q`입니다.


### 감지 중 반복 전송

Sensors → Configure → 각 규칙의 **Repeat · seconds (0 = once)**에서 설정합니다.

- 0: 기존처럼 조건 충족 후 한 번 전송하고 해제·재진입을 기다립니다.
- 1: Hold 동안 연속 감지를 확인한 뒤 처음 전송하고, 이후 새 측정값이 계속 조건을 만족할 때 약 1초마다 전송합니다.
- 반복 모드에서는 Reset margin과 무관하게 조건을 벗어난 첫 측정값에서 멈춥니다. 재진입하면 Hold부터 다시 확인합니다.
- 입력이 끊기면 기존 값을 가지고 반복하지 않습니다. 데이터 타임아웃 이후에는 Hold도 다시 시작합니다.
- 전송이 밀려도 같은 규칙의 요청을 쌓아 한꺼번에 보내지 않습니다. 입력 주기와 응답 지연 때문에 실제 간격은 설정값보다 길어질 수 있습니다.
- Edit signal의 Cooldown도 적용됩니다. 1초 반복을 원하면 해당 Signal의 Cooldown을 0으로 두고 Repeat에서 간격을 제어하세요.
- 이미 HTTP로 보낸 요청은 취소할 수 없습니다. 미감지 시 아직 전송하지 않은 반복 요청은 폐기합니다.

SEN0610 전용 설정은 near > 0.5, Hold 1초, Repeat 1초, person Cooldown 0입니다. 앱을 재실행하고 센서 연결을 연 뒤 Enable all rules를 눌러 적용하세요. ESP32 펌웨어 재업로드는 필요 없습니다.
